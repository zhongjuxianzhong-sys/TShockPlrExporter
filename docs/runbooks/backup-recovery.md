# 备份与恢复 Runbook

## 适用范围

用于解释导出备份、导入前备份、保留策略和误覆盖后的恢复流程。

## 备份类型

| 备份 | 位置 | 创建时机 | 保留策略 |
| --- | --- | --- | --- |
| 导出同名文件备份 | `tshock/PlayerExports/*.plr.bak` | 导出目标 `.plr` 已存在时 | 每个账号最多保留最新 10 份 |
| 导入前 SSC 备份 | `tshock/PlayerSscBackups/*.plr` | 导入前目标账号已有 `tsCharacter` 数据时 | 插件不自动轮转；需自行归档 |
| 全实例备份 | 由服务器管理员决定 | 批量导入、批量导出或数据库维护前 | 按服务器备份策略执行 |

导入前备份失败时，插件不会继续覆盖 SSC。导入成功后，`PlayerImports` 中的源文件仍保留。

## 误覆盖后的恢复

1. 立即通知相关玩家不要继续操作角色，避免在线状态再次写库。
2. 如果目标账号在线，请其退出，或由管理员确保该账号完全离线。
3. 从 `tshock/PlayerSscBackups` 找到最近一次正确备份。
4. 把备份 `.plr` 复制到 `tshock/PlayerImports`。
5. 执行 `/playerimport <账号名|账号ID> <备份文件名>`。
6. 确认导入汇总、备份路径和 trace ID。
7. 让玩家重新登录并核对角色、库存、银行、Loadout 和进度。

## 从导出备份恢复

`.plr.bak` 是导出前的旧人物文件，不是数据库快照。

1. 找到正确的 `.plr.bak`，确认其时间晚于需要恢复的数据版本。
2. 将其复制或重命名为 `.plr`，放到 `tshock/PlayerImports`。
3. 使用 `/playerimport` 导入，不要直接替换 `PlayerExports` 中的当前导出文件。
4. 验证角色后，保留原始备份直到确认恢复完成。

## 数据库级恢复

只有在 `PlayerSscBackups` 也缺失、数据库损坏或批量操作需要整体回滚时，才考虑恢复整个数据库。

1. 停止服务器，避免新连接继续写入。
2. 复制当前数据库和 TShock 日志到独立目录，保留现场。
3. 使用管理员选定的数据库备份恢复。
4. 启动服务器，确认 TShock 正常加载。
5. 抽查账号 SSC 数据和插件命令。

不要在服务器运行时直接覆盖 SQLite 或 MySQL 数据库文件。

## 验证

- 恢复用的 `.plr` 文件存在且非空。
- 导入日志显示目标账号和备份路径。
- 玩家重新登录后的角色状态符合预期。
- 保留日志和备份文件，直到用户确认恢复完成。

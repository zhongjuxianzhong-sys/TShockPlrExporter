# 在线玩家 Runbook

## 适用范围

用于处理导出到过期 SSC 数据、导入时玩家被踢出、目标玩家重新上线或等待离线超时等问题。

## 关键规则

- 在线玩家当前的 Terraria 状态不一定已经写入 `tsCharacter`。
- 导出前，插件会在主线程把目标在线玩家的 `PlayerData` 同步到 SSC。同步失败会记录警告并继续导出，结果可能较旧。
- 启用 `tshock.ignore.ssc` 的在线玩家会被跳过，日志会明确提示导出的可能是旧数据。
- 导入前，目标账号必须离线。插件会踢出匹配账号的在线会话，等待离线并留出清理时间。
- 如果等待超过 15 秒，或玩家在清理窗口内重新上线，导入会中止且不修改 SSC。

## 导出时数据可能过期

1. 在日志中搜索本次 trace ID。
2. 查找 `在线玩家 SSC 数据同步` 或 `跳过 SSC 落库`。
3. 如果同步成功，继续核对输出文件时间与账号 ID。
4. 如果同步失败，让目标玩家正常退出或先触发一次服务器保存，再重新执行导出。
5. 确认目标玩家没有启用 `tshock.ignore.ssc`。

## 导入时目标玩家被踢出

这是预期行为。旧会话稍后保存会覆盖新导入结果，因此导入会先踢出目标账号。

1. 通知相关玩家导入期间不要立即重连。
2. 观察日志中的“准备导入账号”和踢出说明。
3. 等导入成功汇总后，再允许玩家登录。
4. 玩家登录后确认角色数据和库存。

## 等待离线超时

1. 检查目标账号是否在其他连接、代理或会话中仍处于在线状态。
2. 在日志中确认插件等待的是哪个账号 ID 和用户名。
3. 让玩家彻底断开并等待服务器完成断开处理，再重试导入。
4. 不要通过直接写数据库绕过离线检查。
5. 如果服务器主线程卡顿导致踢出队列不执行，转到 [`main-thread-scheduling.md`](main-thread-scheduling.md)。

## 玩家重新上线导致中止

导入会检测目标账号是否在踢出后重新出现。这是保护措施，避免旧会话覆盖新 SSC。

1. 再次踢出或请玩家彻底退出。
2. 确认账号离线后重新执行 `/playerimport`。
3. 如连续发生，检查登录白名单、自动重连或其他插件是否会在踢出后立即拉回玩家。

## 验证

- 导入完成日志包含成功账号、备份路径和 trace ID。
- 导入成功后目标账号重新登录，角色应符合源 `.plr`。
- 若数据仍像旧角色，先停止继续写入，检查是否还有在线旧会话，再按 [`backup-recovery.md`](backup-recovery.md) 评估恢复。

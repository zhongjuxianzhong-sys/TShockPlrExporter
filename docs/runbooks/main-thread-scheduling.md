# 主线程调度 Runbook

## 适用范围

用于处理“只显示任务已开始但没有结果”、任务长时间占用、玩家收不到消息、导入踢出不动或主线程队列停摆。

## 调度模型

- 导入和导出重活运行在后台线程。
- 在线玩家消息、在线 SSC 同步、导入踢出和导出回退保存需要回到 Terraria 主线程。
- `MainThreadQueue.Drain` 由 TShock `GameUpdate` 钩子抽取。
- `MainThreadQueue.Invoke` 等待主线程执行的默认超时为 15 秒。
- 队列超过 5 秒没有被抽取时，插件会记录主线程队列停摆警告。

## 只显示“任务已开始”

1. 在日志中搜索本次 trace ID 或 `[TShockPlrExporter]`。
2. 如果看到完成汇总，说明结果已写日志，问题只影响游戏内消息投递。
3. 如果看到主线程队列停摆警告，检查 TShock 主循环是否仍在运行、服务器是否严重卡顿或正在关闭。
4. 如果看到后台任务异常终止，按异常堆栈处理，不要直接重启并重复执行写入任务。
5. 如果日志完全没有后续记录，检查服务器是否在任务期间被强制关闭。

## 提示“已有玩家存档任务正在执行”

1. 记录提示中的已运行秒数。
2. 查日志确认当前任务类型和 trace ID。
3. 若接近数据库 30 秒超时或主线程 15 秒超时，等超时路径返回结果。
4. 若持续数分钟不结束，按“任务卡住”处理。

## 任务卡住

1. 先确认服务器主线程是否仍在响应普通 TShock 命令。
2. 查最新日志中的数据库、队列停摆、踢出等待或文件写入异常。
3. 如果卡在导入写入阶段，先备份数据库和日志，再停止服务器；不要并行启动另一个实例继续写同一数据库。
4. 如果卡在等待在线玩家离线，检查 [`online-players.md`](online-players.md)。
5. 如果卡在数据库查询，检查 [`database-backends.md`](database-backends.md)。
6. 重启后用 `/api` 之外的普通 TShock 操作确认插件版本和命令加载正常，再在无人在线或低峰期重试。

## 结果消息投递失败

- 控制台结果不依赖 `GameUpdate`，应能直接写控制台和日志。
- 在线玩家消息通过 `MainThreadQueue.Enqueue` 投递；队列停摆时玩家收不到消息是预期后果。
- 结果汇总始终应写日志。以日志为准恢复操作状态，不要根据聊天是否收到重复执行导入。

## 验证

- 日志中能看到任务开始、完成汇总和 trace ID。
- 没有持续的“主线程队列已有 N 秒没有被抽取”警告。
- 目标文件生成、备份存在、导入目标离线且后续登录正常。
